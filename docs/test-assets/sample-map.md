# Sample ROS map fixture

## Path

```text
web/public/test-maps/sample/map.pgm
web/public/test-maps/sample/map.yaml
```

Served by Vite at:

```text
/test-maps/sample/map.pgm
/test-maps/sample/map.yaml
```

## Purpose

Development / test fixture for the Admin Map Editor import flow.

Admin (or a "Load Sample Map" button in DEV) uploads these files through the **same** multipart API used for a real RPLIDAR map:

`POST /api/navigation/warehouses/{warehouseId}/maps/import`

After import, the Map Editor must use only:

- MapVersion API metadata
- `PreviewImageUri` (backend-generated PNG under `/map-assets/...`)

It must **not** keep reading `/test-maps/sample/...`.

## PGM format

| Field | Value |
|-------|--------|
| Magic | `P5` (binary grayscale) |
| Comment | `# Generated by OpenCV 3.2.0` |
| Size | 1192 × 918 |
| Maxval | 255 |
| Approx file size | ~1.09 MB |

## YAML summary

```yaml
image: submap_0.pgm
resolution: 0.037721614
origin: [-5.000000, -5.000000, 0.000000]
negate: 0
occupied_thresh: 0.65
free_thresh: 0.196
```

Notes:

- `image:` in the YAML names the original SLAM output (`submap_0.pgm`). On import the backend stores the uploaded bytes as `map.pgm` and ignores the YAML filename for storage.
- `origin` yaw is `0` (radians).
- Units: `resolution` m/px; origin X/Y meters; origin yaw radians.
